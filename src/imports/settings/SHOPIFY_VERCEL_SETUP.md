# Pottlerkinder: Shopify + Vercel с нуля

Это руководство для ситуации, когда сайт Pottlerkinder — красивый **фронтенд на Vercel**, а Shopify — место, где вы управляете магазином: товарами, ценами, остатками, заказами, клиентами, доставкой и оплатой.

Ничего секретного нельзя писать в `App.tsx`, `src/` или отправлять в чат. Ключи добавляются только в настройках Vercel.

---

## Как проходить настройку вместе с этим чатом

Не пытайтесь сделать всё за один раз. Выполняйте пункты в указанном порядке и после **каждого** пункта возвращайтесь в этот чат. Я буду добавлять или менять код только тогда, когда вы напишете нужный запрос.

### До первого деплоя

| Вы сделали | Что написать в чат |
|---|---|
| Создали магазин Shopify | `Магазин Shopify создан, что делать дальше?` |
| Создали товары, варианты, коллекции и теги | `Товары в Shopify готовы, подключи каталог к Shopify API.` |
| Настроили доставку и оплату | `Shopify доставка и оплата готовы, проверь что нужно в коде до деплоя.` |
| Создали Shopify custom app и получили ключи | `Shopify API ключи получил. Скажи куда их безопасно добавить в Vercel.` |
| Создали проект Supabase | `Supabase проект создан. Подключи авторизацию админ-панели.` |
| Добавили себя с ролью admin | `Supabase admin создан. Сделай закрытую админ-панель.` |
| Готовы опубликовать | `Проверь проект перед первым деплоем на Vercel.` |

Не присылайте в чат настоящие токены, пароли, ключи, UUID сессий или `service_role key`. Достаточно написать, что шаг выполнен.

### Во время деплоя на Vercel

1. Сначала напишите: `Я настраиваю Vercel, дай следующий шаг.`
2. Выполните ровно один шаг из ответа.
3. Добавили переменную окружения — напишите: `Переменные Shopify добавлены в Vercel.`
4. Добавили переменные Supabase — напишите: `Переменные Supabase добавлены в Vercel.`
5. Перед нажатием **Deploy** напишите: `Проверь, всё ли готово к деплою.`
6. После успешного Deploy напишите: `Vercel задеплоен, что проверяем первым?`
7. Если увидите ошибку, скопируйте в чат полный текст ошибки или приложите скриншот: `Ошибка Vercel: ...`.

### После каждого деплоя

После любого повторного деплоя выполняйте проверку по порядку и после каждого результата пишите в чат:

1. Открылся сайт: `Сайт открылся.`
2. Открылся каталог: `Каталог открылся, товары [видны/не видны].`
3. Работает корзина: `Корзина [работает/ошибка: ...].`
4. Открылся Shopify Checkout: `Checkout [открылся/ошибка: ...].`
5. Создан тестовый заказ: `Тестовый заказ [создан/ошибка: ...].`
6. Открылся `/admin`: `Админ-вход [работает/ошибка: ...].`
7. Изменён тестовый товар: `Товар из админки [изменился/не изменился].`

Перед тем как менять товар, оплату, доставку, API-ключ, Supabase или Vercel, пишите, например: `Хочу поменять [что именно]. Что мне сделать в Shopify, Vercel и коде?` Так вы не сломаете работающую часть магазина.

## Как это будет работать

1. Покупатель открывает сайт Pottlerkinder на Vercel.
2. Сайт получает товары и варианты из Shopify через API.
3. Покупатель добавляет вариант товара в корзину.
4. Корзина создаётся в Shopify. Цены, скидки, наличие и доставка считаются именно там.
5. Кнопка оплаты отправляет покупателя на защищённую страницу Shopify Checkout.
6. В Shopify покупатель оплачивает заказ; Shopify создаёт заказ, уменьшает остатки и отправляет письма.
7. Вы в Shopify редактируете товар, цену, фото, заказ или клиента — фронтенд не нужно менять для обычных правок.

# Часть A. Настройка Shopify

## Шаг 1. Создайте магазин

1. Откройте [shopify.com](https://www.shopify.com/) и создайте магазин.
2. Выберите временный адрес вида `название.myshopify.com`.
3. В панели Shopify слева вы увидите разделы **Products**, **Orders**, **Customers**, **Content**, **Online Store**, **Settings**. Вся повседневная работа с магазином будет происходить здесь.
4. Не удаляйте адрес `*.myshopify.com`: он нужен API даже после подключения собственного домена.

## Шаг 2. Заполните данные компании

Откройте **Settings → Store details**.

1. Впишите юридическое название, адрес, e-mail, телефон, валюту EUR.
2. В **Settings → Taxes and duties** настройте НДС с бухгалтером. Для Германии обычно требуется корректная ставка 19%, но юридические настройки лучше проверить у специалиста.
3. В **Settings → Policies** добавьте или вставьте подготовленные юридические страницы: Impressum, Datenschutz, AGB, Widerruf, Versandbedingungen. Shopify добавит ссылки в checkout.

## Шаг 3. Добавляйте товары только в Shopify

Откройте **Products → Add product**.

Для каждого товара:

1. Укажите название, например `FÖRDERTURM HOODIE`.
2. Добавьте описание, фото, цену и цену до скидки (`Compare-at price`), если это sale.
3. В блоке **Inventory** включите отслеживание остатков, если нужно.
4. В блоке **Shipping** укажите вес — Shopify использует его для доставки.
5. В **Variants** создайте реальные варианты: цвет, размер XS–3XL, детские размеры 104–152. У каждого варианта должны быть свои цена, SKU и остаток при необходимости.
6. В **Product organization** заполните тип товара, коллекции и теги.
7. Нажмите **Save**, затем поставьте статус **Active**.

### Рекомендуемая структура в Shopify

Создайте автоматические или ручные коллекции:

* `Frauen`
* `Männer`
* `Kinder`
* `Hoodies`
* `Sweatshirts`
* `T-Shirts`
* `Polos`
* `Accessoires`
* `Gläser & Tassen`
* `DTF-Transfers`
* `Sale`

Создайте одинаковые теги для фильтрации, например:

```text
gender_frauen
gender_maenner
gender_kinder
gender_unisex
category_hoodies
category_sweatshirts
category_tshirts
category_polos
category_accessoires
category_glaeser_tassen
category_dtf
color_schwarz
color_rot
```

Так фронтенд сможет строить все текущие фильтры без ручного редактирования товаров в коде.

## Шаг 4. Настройте доставку

Откройте **Settings → Shipping and delivery**.

1. Создайте рынок/зону доставки, например Germany, затем нужные страны ЕС.
2. Для каждой зоны добавьте тарифы: фиксированная цена или расчёт перевозчика.
3. Добавьте бесплатную доставку: **Add rate → Free shipping → Minimum order price → 80 EUR**.
4. Проверьте в тестовой корзине, что до 80 EUR показывается обычная доставка, а от 80 EUR — бесплатная.

Доставку, налог и цену доставки сайт не должен вычислять сам: Shopify сделает это в checkout.

## Шаг 5. Настройте оплату

Откройте **Settings → Payments**.

1. Подключите Shopify Payments, PayPal, Klarna или доступные для вашей страны способы оплаты.
2. Пройдите проверку компании, если Shopify её запросит.
3. Для тестов включите test mode только пока не принимаете реальные заказы.
4. Никогда не добавляйте форму ввода данных банковской карты в этот React-сайт. Оплата должна проходить в Shopify Checkout — это безопасно и соответствует требованиям PCI.

## Шаг 6. Настройте покупателей

Откройте **Settings → Customer accounts**.

1. Включите аккаунты покупателей.
2. Для API, который сейчас подготовлен в проекте, выберите совместимый вариант **Legacy customer accounts**, если он доступен в вашем магазине.
3. Если Shopify предлагает только новые Customer Accounts, корзина и checkout продолжат работать, но вход/регистрация потребуют отдельной OAuth-интеграции Customer Account API. Не пытайтесь обходить это ключом Admin API.
4. В **Customers** вы сможете видеть покупателей, менять заметки, теги и историю заказов. Пароли покупателей Shopify хранит самостоятельно — вы их не увидите и не должны хранить на сайте.

## Шаг 7. Настройте скидки

Откройте **Discounts → Create discount**.

1. Для SALE используйте `Compare-at price` у товара или скидку Shopify.
2. Для промокода создайте Code discount.
3. Для автоматической акции создайте Automatic discount.
4. Shopify применит подходящие скидки в checkout. Не храните расчёт скидок только во фронтенде.

# Часть B. Создание Shopify API-приложения

## Шаг 8. Откройте раздел приложений

1. В Shopify откройте **Settings → Apps and sales channels**.
2. Нажмите **Develop apps**.
3. Если Shopify просит разрешить custom app development, подтвердите для своего магазина.
4. Нажмите **Create an app**.
5. Название: `Pottlerkinder Vercel API`.
6. Выберите себя как разработчика приложения.

## Шаг 9. Получите Storefront API token

Этот ключ используется для магазина: читать товары, работать с корзиной и аккаунтом покупателя. Он не должен давать права на удаление товаров.

1. В новом приложении откройте **Configuration → Storefront API integration**.
2. Включите минимум прав, которые предлагает Shopify для:
   - чтения товаров и коллекций;
   - чтения наличия;
   - работы с корзиной/checkout;
   - работы с customer accounts, если доступно.
3. Нажмите **Save**.
4. Откройте **API credentials** и нажмите **Install app**.
5. Скопируйте **Storefront API access token** в безопасное временное место. Он понадобится на следующем шаге.

## Шаг 10. Получите Admin API token

Этот ключ очень опасен: он может менять товары и видеть служебные данные. Он остаётся только на сервере Vercel.

1. В **Configuration → Admin API integration** включите только нужные права:
   - `read_products`, `write_products`;
   - `read_inventory`, `write_inventory`, если редактируете остатки;
   - `read_orders`, если нужна собственная панель заказов.
2. Не включайте лишние права.
3. Нажмите **Save → API credentials → Install app**.
4. Скопируйте **Admin API access token**.
5. Не вставляйте этот токен в `App.tsx`, `.env` в Git, Notion, скриншот или публичный чат.

# Часть D. Что ещё нужно подключить в интерфейсе

Эта часть объясняет, как тестовый интерфейс превращается в настоящий магазин. Сейчас в `src/App.tsx` находится временный массив `CATALOG_PRODUCTS` из 100 тестовых карточек. Они нужны только для дизайна: Shopify пока о них ничего не знает, а сайт пока не получает реальные товары автоматически.

Вам не нужно разбираться в React и не нужно самостоятельно менять эти файлы. Выполняйте действия в Shopify/Vercel и после каждого шага отправляйте в этот чат указанную короткую фразу. Я буду делать изменения в коде по этапам.

## D.1. Подготовьте Shopify до подключения интерфейса

До первого запроса в чат проверьте в Shopify каждый реальный товар:

1. Откройте **Products → нужный товар**.
2. У товара есть название, описание и минимум одно изображение.
3. Статус товара — **Active**.
4. В **Publishing** товар опубликован в канале, который использует Storefront API. Если товар не опубликован, сайт его не увидит.
5. В **Variants** есть реальные варианты. Например, у худи: цвет `Schwarz`, размер `S`; цвет `Schwarz`, размер `M`; и так далее.
6. У каждого варианта заполнена цена и, если нужно, количество на складе.
7. У товара стоят нужные коллекции и теги из частей A.3 и A.4 этой инструкции.
8. Сохраните товар.

Сделайте один тестовый товар полностью, а не сто товаров сразу. На нём проще проверить корзину, размер, цену и оплату.

После этого напишите в чат:

```text
Первый товар в Shopify полностью заполнен. Подключи каталог к Shopify.
```

## D.2. Что будет сделано в коде: настоящий каталог

После этого сообщения я внесу кодовые изменения. Вам ничего копировать или вставлять не нужно.

1. Будет создан публичный серверный endpoint Vercel, который запрашивает у Shopify только опубликованные товары.
2. Тестовый массив `CATALOG_PRODUCTS` перестанет быть источником каталога.
3. Каталог сайта начнёт показывать название, фото, цену, цену распродажи, наличие, тип товара, коллекции и варианты из Shopify.
4. Страница категории (`Hoodies`, `T-Shirts`, `Accessoires` и т. д.) станет фильтровать реальные товары Shopify.
5. Карточка товара будет открывать настоящий товар по его Shopify `handle` — это безопасное название товара в ссылке, например `/katalog/foerderturm-hoodie`.
6. Лимит 50 карточек и переключение страниц останутся, но данные будут приходить из Shopify, а не из тестового списка.
7. Блок Bestseller будет выбирать до 20 реальных товаров из каталога.
8. Sale будет показывать только товары с `Compare-at price` или специальной коллекцией/тегом `Sale` — точный вариант будет выбран при подключении.

После изменения кода я попрошу открыть сайт и проверить одну карточку. Вы напишете:

```text
Каталог Shopify подключён. Проверил товар: [виден/не виден/ошибка].
```

Если товар не виден, не меняйте код. Сначала проверьте в Shopify статус `Active`, публикацию и наличие варианта.

## D.3. Как сайт понимает размер, цвет и товар

В Shopify один товар может иметь много вариантов. Например:

```text
Товар: FÖRDERTURM HOODIE
Вариант 1: Schwarz / S / 40,90 €
Вариант 2: Schwarz / M / 40,90 €
Вариант 3: Rot / S / 40,90 €
```

На сайте будет происходить следующее:

1. Покупатель открывает `FÖRDERTURM HOODIE`.
2. Сайт получает все варианты этого товара из Shopify.
3. Покупатель выбирает цвет и размер.
4. Сайт находит ровно один Shopify Variant ID, соответствующий этому цвету и размеру.
5. В корзину добавляется не просто «худи», а конкретный вариант, например `Schwarz / M`.
6. Shopify проверяет остаток и возвращает настоящую цену.

Чтобы это работало, в Shopify называйте опции одинаково у всех товаров:

| Что | Как лучше назвать в Shopify |
|---|---|
| Опция 1 | `Farbe` |
| Опция 2 | `Größe` |
| Цвета | `Schwarz`, `Weiß`, `Rot` и т. п. |
| Размеры взрослых | `XS`, `S`, `M`, `L`, `XL`, `2XL`, `3XL` |
| Детские размеры | `04A (104)`, `06A (116)`, `08A (128)`, `10A (140)`, `12A (152)` |

Не называйте один и тот же цвет одновременно `black`, `Schwarz` и `schwarz`: фильтр будет считать их разными цветами.

После создания вариантов для основных товаров напишите:

```text
Варианты цветов и размеров в Shopify заполнены одинаково. Подключи выбор вариантов на странице товара.
```

## D.4. Что будет сделано в коде: кнопка «в корзину»

В проекте уже есть `api/cart.js` и `src/lib/shopify.ts`. Это подготовленная логика, но кнопки интерфейса ещё должны быть к ней привязаны.

После вашего сообщения я сделаю следующее:

1. Добавлю на странице товара активную кнопку `IN DEN WARENKORB`.

# Часть E. Закрытая админ-панель на сайте

Да, это можно и нужно делать безопасно. Админ-панель будет частью сайта, например по адресу `ваш-сайт.de/admin`, но обычный покупатель не сможет в неё попасть.

## Как это устроено

1. Вы открываете `/admin` и входите по отдельному логину сотрудника.
2. Сервер Vercel проверяет, что вы действительно администратор.
3. Панель отправляет запрос не прямо в Shopify, а в защищённый endpoint Vercel `/api/admin/products`.
4. Только Vercel хранит секретный Shopify Admin API token.
5. Vercel отправляет изменение в Shopify.
6. Shopify сохраняет товар, цену, варианты, остатки и фото. Сайт при следующем запросе показывает обновлённые данные.

Покупатели никогда не получают Admin API token и не могут удалить или изменить товары через браузер.

## Что будет доступно в панели

* список товаров, поиск и фильтры;
* создать товар;
* поменять название, описание, цену, цену до скидки, теги, коллекции и статус;
* добавить/изменить размеры, цвета, SKU и остатки вариантов;
* загрузить или удалить фотографии;
* удалить товар с обязательным подтверждением;
* открыть товар в Shopify для расширенных настроек;
* видеть последние изменения и ошибки Shopify.

Заказы, возвраты, выплаты, налоги, доставка и платежи лучше продолжать вести в Shopify Admin: там это уже юридически и технически безопасно.

## Важное различие между админом и покупателем

| Кто | Где входит | Что может делать |
|---|---|---|
| Покупатель | `/login` | профиль, адреса, история своих заказов, корзина |
| Администратор | `/admin` | редактировать товары сайта |
| Shopify владелец | Shopify Admin | всё: платежи, заказы, доставка, возвраты, сотрудники |

У администратора сайта должен быть **отдельный** аккаунт. Не используйте один пароль для покупателей, Shopify и администратора сайта.

## Какую авторизацию использовать

Самый надёжный и удобный вариант — **Supabase Auth**:

1. Создаётся отдельная база пользователей сотрудников.
2. Вы добавляете свой e-mail как администратора.
3. Вход выполняется по e-mail и паролю либо magic link.
4. Сессия хранится в защищённой cookie.
5. Каждый запрос к `/api/admin/*` проверяет сессию и роль `admin` на сервере.

Можно использовать Clerk, Auth0 или собственную авторизацию, но не нужно делать админ-вход просто по паролю в React, localStorage или URL. Текущий `POTTLER_ADMIN_SECRET` — это временная защита server endpoint, а не полноценная система входа для интерфейса.

## Пошаговая настройка Supabase Auth для администратора

Ниже описан вариант, который не требует знания программирования. Supabase будет хранить только учётные записи сотрудников и их роли. Товары, клиенты, корзины, платежи и заказы остаются в Shopify.

### E.1. Создайте проект Supabase

1. Откройте [supabase.com](https://supabase.com/) и нажмите **Start your project**.
2. Войдите через GitHub. Лучше использовать тот же GitHub, через который подключён Vercel.
3. Нажмите **New project**.
4. Выберите организацию или создайте новую.
5. Введите имя, например `pottlerkinder-admin`.
6. Задайте сильный пароль базы данных и сохраните его в менеджере паролей. Этот пароль не нужен для входа в админ-панель.
7. Выберите регион, ближайший к Германии/вашим покупателям.
8. Нажмите **Create new project** и дождитесь, пока статус станет зелёным — это может занять несколько минут.

### E.2. Получите два публичных значения для сайта

1. В Supabase откройте созданный проект.
2. Слева откройте **Project Settings → API**.
3. Найдите и скопируйте:
   - **Project URL** — начинается с `https://...supabase.co`;
   - **Publishable key** или **anon public key**.
4. Это не пароли. Их можно использовать во фронтенде сайта.
5. Ниже будет **service_role key**. Не копируйте его в React, не добавляйте в `VITE_...`, не отправляйте никому. Он нужен только серверу Vercel на следующем этапе разработки.

### E.3. Включите вход по e-mail

1. В Supabase слева откройте **Authentication → Providers**.
2. Откройте **Email**.
3. Включите Email provider.
4. На этапе настройки можно выключить **Confirm email**, чтобы не ждать письма. Перед реальным запуском лучше включить подтверждение e-mail.
5. Сохраните изменения.

### E.4. Укажите адреса сайта для входа

1. Откройте **Authentication → URL Configuration**.
2. В поле **Site URL** укажите адрес Vercel, например `https://pottlerkinder.vercel.app`.
3. В **Redirect URLs** добавьте каждый адрес с новой строки:

```text
https://pottlerkinder.vercel.app/admin
https://pottlerkinder.vercel.app/**
http://localhost:5173/admin
http://localhost:5173/**
```

4. Когда подключите собственный домен, добавьте также:

```text
https://ваш-домен.de/admin
https://ваш-домен.de/**
```

5. Нажмите **Save**. Без этого письма входа могут возвращать пользователя на неправильный адрес.

### E.5. Создайте таблицу ролей

Обычный пользователь, зарегистрированный в Supabase, ещё не должен становиться администратором. Роль будет храниться отдельно.

1. Слева в Supabase откройте **SQL Editor**.
2. Нажмите **New query**.
3. Вставьте весь код ниже и нажмите **Run**:

```sql
create table if not exists public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  email text,
  role text not null default 'staff' check (role in ('admin', 'staff')),
  created_at timestamptz not null default now()
);

alter table public.profiles enable row level security;

create policy "Users can read own profile"
on public.profiles for select
to authenticated
using (auth.uid() = id);
```

4. Если увидите зелёное сообщение, таблица создана.
5. Не добавляйте policy, позволяющую всем менять поле `role`. Иначе любой вошедший пользователь сможет сделать себя администратором.

### E.6. Создайте свой админ-аккаунт

1. Откройте **Authentication → Users**.
2. Нажмите **Add user → Create new user**.
3. Введите свой рабочий e-mail и длинный уникальный пароль.
4. Нажмите **Create user**.
5. Откройте пользователя и скопируйте его **UUID** / `User UID`.
6. Вернитесь в **SQL Editor → New query**.
7. Замените текст `ВСТАВЬТЕ_UUID` и `ваш@email.de` в этом примере, затем нажмите **Run**:

```sql
insert into public.profiles (id, email, role)
values ('ВСТАВЬТЕ_UUID', 'ваш@email.de', 'admin')
on conflict (id) do update set role = 'admin', email = excluded.email;
```

8. В **Table Editor → profiles** убедитесь, что у вашей строки в колонке `role` написано `admin`.
9. Для нового сотрудника повторите шаги 1–5, но укажите роль `staff`. Доступ к редактированию товаров должен получать только `admin`.

### E.7. Добавьте Supabase в Vercel

1. Откройте Vercel → ваш проект → **Settings → Environment Variables**.
2. Нажмите **Add New** и добавьте:

| Имя переменной | Что вставить | Можно ли видеть в браузере |
|---|---|---|
| `VITE_SUPABASE_URL` | Project URL из E.2 | да |
| `VITE_SUPABASE_ANON_KEY` | Publishable/anon key из E.2 | да |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key из E.2 | нет, только Vercel server API |

3. Для каждой переменной отметьте `Production`, `Preview` и `Development`.
4. Нажмите **Save**.
5. Откройте **Deployments** и запустите **Redeploy** последнего деплоя.

Переменные с `VITE_` Vite специально передаёт в браузер. Поэтому туда можно добавлять только URL и anon key. `SUPABASE_SERVICE_ROLE_KEY` не должен начинаться с `VITE_`.

### E.8. Что будет добавлено в проект

При реализации админ-панели в код добавляются:

1. Пакет `@supabase/supabase-js`.
2. Файл `src/lib/supabase.ts` — подключение фронтенда только по `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
3. Страница `/admin/login` — форма входа.
4. Страница `/admin` — список и редактор товаров.
5. Защита маршрута: нет сессии → перейти на `/admin/login`; есть сессия без роли `admin` → показать «нет доступа».
6. Серверная проверка сессии во всех `api/admin/*` файлах.
7. Защищённая cookie сессии, чтобы вход не исчезал при обновлении страницы.

Вам не нужно создавать эти файлы вручную и не нужно вставлять ключи в код. В код добавляется только обращение к именам переменных; их реальные значения живут в Vercel.

### E.9. Как вы будете входить после настройки

1. Откройте `https://ваш-домен.de/admin`.
2. Если вы не вошли, сайт покажет `/admin/login`.
3. Введите e-mail и пароль из E.6.
4. После входа сайт проверит таблицу `profiles`.
5. Если роль `admin`, откроется панель товаров.
6. Если роль `staff`, будет сообщение «Нет доступа».
7. Чтобы выйти, нажмите «Выйти» в админ-панели.

### E.10. Что делать, если доступ потерян

1. Войдите в Supabase через GitHub.
2. Откройте **Authentication → Users** и создайте нового пользователя.
3. Повторите E.6: добавьте его UUID в `profiles` с ролью `admin`.
4. Старого пользователя можно удалить или поменять ему пароль в Supabase.
5. Если случайно раскрыли `SUPABASE_SERVICE_ROLE_KEY`, немедленно в Supabase откройте **Project Settings → API**, смените ключ и замените его в Vercel, затем сделайте Redeploy.

### E.11. Чек-лист безопасности

* В Vercel `SUPABASE_SERVICE_ROLE_KEY` не имеет префикса `VITE_`.
* В Git нет настоящих ключей и нет файла `.env` с ключами.
* В `profiles` роль `admin` есть только у нужных людей.
* В Supabase включён RLS для `profiles`.
* У `api/admin/*` есть серверная проверка Supabase-сессии, а не только скрытая кнопка на сайте.
* Shopify Admin token остаётся только в Environment Variables Vercel.
* На реальном домене используется HTTPS (Vercel делает это автоматически).

## Что потребуется сделать в коде

Для полноценной панели нужны следующие доработки:

1. Создать страницу `/admin` и форму входа.
2. Подключить провайдер авторизации сотрудников (рекомендуется Supabase Auth).
3. Добавить таблицу ролей: пользователь с ролью `admin` может войти; все остальные получают 403.
4. Изменить `api/admin/products.js`: вместо передачи `POTTLER_ADMIN_SECRET` из браузера проверять защищённую сессию сотрудника на Vercel.
5. Добавить endpoints для фото, вариантов, остатков, коллекций и тегов Shopify.
6. Создать интерфейс редактирования с подтверждением удаления и понятным отображением ошибок.
7. Подключить каталог сайта к Shopify Storefront API, чтобы изменения из админ-панели сразу появлялись в каталоге.

После этого вы сможете редактировать товары на своём сайте. Изменения будут сохраняться в Shopify, а Shopify останется единственным источником правды для ассортимента.

## Что не нужно делать вручную

* Не давайте Shopify Admin API token фронтенду.
* Не записывайте token в `App.tsx`, `.env` в Git или в код админ-страницы.
* Не создавайте админа как обычного покупателя Shopify.
* Не переносите оплату в админ-панель: оплату всегда ведёт Shopify Checkout.
* Не редактируйте одновременно один товар в Shopify и на сайте в двух вкладках — обновляйте страницу после сохранения.

## Корзина и оплата при наличии админ-панели

Админ-панель никак не меняет путь покупателя:

```text
Сайт Pottlerkinder → Shopify Cart API → Shopify Checkout → оплата → Shopify Orders
```

Корзина, скидки, доставка, налоги, платежи и заказы остаются в Shopify. Панель редактирует только ассортимент и не получает платёжные данные покупателя.

# Если что-то не работает

| Симптом | Что проверить |
|---|---|
| API пишет `Missing SHOPIFY...` | переменная не добавлена в Vercel или не сделан Redeploy |
| Товар не виден | статус Active, опубликован в нужном sales channel, корректная коллекция/тег |
| Корзина не создаётся | Storefront token и права Storefront API |
| Редактирование товара возвращает 401 | неверный `POTTLER_ADMIN_SECRET` или нет `Authorization: Bearer ...` |
| Редактирование возвращает Shopify error | проверьте права Admin API и Shopify product ID |
| Оплата не проходит | Settings → Payments и test mode в Shopify |

Сначала всегда проверяйте Shopify и Vercel Environment Variables; код фронтенда менять ради цены, фото, товара, скидки, заказа или доставки не нужно.
