# Подготовка магазина к публикации

## Структура

- `src/components/` — React-компоненты.
- `src/styles/components/` — их стили; общие стили — `src/styles/`.
- `src/index.css` — точка входа Tailwind и существующие глобальные стили.
- `src/assets/site/` — логотипы, категории, баннеры, изображения страниц.
- `src/assets/designer/` — рабочие изображения конструктора, сгруппированные по изделию, стороне и цвету.
- `src/assets/company/`, `history/`, `news/`, `payments/`, `fonts/` — тематические ресурсы.
- `src/assets/documents/` — PDF, который предлагается скачать в Blog.
- `docs/reference/` — исходные юридические документы, координаты печати и историческая передача проекта; эти файлы не входят в клиентскую сборку.
- `docs/setup/` — инструкция Shopify/Vercel; `docs/contact-form.md` — Web3Forms.

## Каталог и корзина

Витрина получает товары только через `/api/products` из Shopify. Локальные
демотовары, генераторы тестового каталога и симуляция корзины удалены.
При сбое API выводится сообщение об ошибке, а не подставной ассортимент.
При пустом ответе показывается пустой каталог.

Старый ключ `pottlerkinder-demo-cart` удаляется при инициализации корзины.
Настоящий `pottlerkinder-cart-id` и операции Shopify сохранены.
Отсутствующее фото заменяется нейтральной заглушкой, не фотографией другого товара.
Товары в самом Shopify не удалялись и не изменялись.

## Проверки перед деплоем

```sh
node scripts/check-assets.mjs
node --experimental-strip-types --test tests/*.test.mjs
pnpm build
```

Проверка ресурсов учитывает статические импорты, CSS URL, HTML и динамические
`import.meta.glob` конструктора. Отсутствующие ссылки завершают проверку ошибкой;
неиспользуемые ресурсы выводятся отдельно и не удаляются автоматически.

Изображения сжаты в WebP без изменения размеров, кадрирования, сторон и зон
печати. JPEG заменены на WebP там, где это уменьшает вес; прозрачная таблица
размеров переведена в WebP без потерь.

Результат этой подготовки:

- 527 WebP: 44,28 → 27,98 МБ.
- 29 JPEG/PNG → WebP: 2,16 → 0,48 МБ.
- Удалены 75 неподключённых изображений (4,15 МБ), устаревшие макеты шапки,
  исходный неиспользуемый скриншот и стандартный favicon.
- После очистки и до сжатия сборка занимала 54,65 МБ; после сжатия — 36,70 МБ
  (примерно −33%). Это размер всей папки `dist`, не начальная загрузка страницы.
- Прошли 48 тестов, проверка ссылок на ресурсы и production-сборка.
- Браузерная проверка с подменой API подтвердила каталог без демотоваров,
  пустой/ошибочный ответ, создание/чтение/изменение/удаление корзины и загрузку
  основных страниц без сломанных видимых изображений.
- Настоящие API Shopify, платёж и получение писем эта проверка не подтверждает.

Сборка всё ещё предупреждает о крупном JS-чанке (>500 КБ): основная логика
конструктора остаётся в `App.tsx`. Это не ошибка сборки; отдельное разбиение
конструктора на ленивые модули требует самостоятельного рефакторинга.

Для оценки **новых исходных** WebP-файлов:

```sh
node scripts/optimize-images.mjs
# Применить после проверки результата:
node scripts/optimize-images.mjs --write
```

Не запускайте повторное сжатие уже оптимизированных файлов без необходимости:
повторное lossy-кодирование не улучшает качество. Скрипт не меняет геометрию и
сохраняет оригинал, если выигрыш меньше 10%.

## Что требует проверки на Vercel

- Переменные Shopify и Web3Forms в нужных окружениях и новый Redeploy.
- Получение актуального ассортимента, добавление товара, изменение количества,
  удаление и переход на настоящий Shopify Checkout.
- Реальная доставка Kontakt/Newsletter. Newsletter отправляет заявку, но не
  заменяет сервис рассылок и Double-Opt-In.
- Индексация: в `.figma/make/site.json` сейчас установлено `robots.index: false`.
  Это намеренно не изменялось при очистке ресурсов; перед публичным запуском
  примите решение, нужно ли открывать сайт поисковикам.

Не помещайте секретные переменные или токены в этот документ.
